# 前序评审与讨论处置

| 前序事项 | v1.2处理 | 仍需实施验证 |
|---|---|---|
| R1 创建中删除依赖Register阶段 | 删除Register前置；按Gov未发/已尝试、owner未外部写/已写划分；DELETE信封带完整原charge和计划；未发撤销单事务 | 普通CREATE/DELETE交错、领取竞争、DELETE先到；投影状态不参与退款 |
| R2 老分配证据不失效 | binding适配器显式确认并退休覆盖范围旧事实；投影ENDED不触发物理释放 | 真实证据源未提供；脚本只验证输入正确时的归并 |
| R3 stable ordinal与控制器不兼容 | 不强制ordinal，稳定业务引用+实际Pod UID/container/device；冻结副本数 | 真实Inference渲染及重建、额外rollout入口限制 |
| R4 BOSS需要无租户容量上下文 | 新独立AdminGetCapacity、AdminRead，无tenant=0资源身份 | mTLS+当前角色/平台权限 |
| R5 无关设备冲突导致全部查询失败 | 参考代码先按cluster/device过滤再合并，异常局部返回 | 真实观测全量接线回归 |
| 容量预检阻挡等待 | 静态合法/额度通过可提交，当前容量0或未知只提示 | 前端表单与Gov适配不以reference数量做准入上限 |
| 过期资源无法删除 | 受控管理员/系统删除入口走相同owner清理 | 对应现有权限与审计路径确认 |
| Consumer由Gov发起 | 异步SyncGpuUsage，不在创建/删除关键路径；ID直接用Gov资源引用 | 同步故障、绑定先到、终态先到、同版本冲突 |
| 其他配额是否也需Consumer | 不需要；GPU使用投影为本领域资源查询，不是配额内核概念 | 未来各业务类型保持独立事实权威 |
| gpu-memory-factor | 新MemoryEncoding和ProviderBaseline；q=m/F精确换算、计额MiB不变 | 有效factor及容器实际限制、Node注解/资源上报 |
| 真实预留与动态切换 | 不提供相关RPC/SQL，只保留未来边界 | 未来独立评审，不反向阻塞本次 |

本版对GPU源Proto进行了结构性收敛，不保证与v1.1尚未实施草案声明完全兼容。如果已经有人基于v1.1发布了正式SDK/服务，需要在实施前另定API版本或兼容处理，不能直接热替换。本次不依据设计文件存在而推定线上调用者存在。
