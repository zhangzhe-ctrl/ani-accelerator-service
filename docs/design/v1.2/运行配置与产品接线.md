# 运行配置、BFF字段和现有仓库接线

本章字段是v1.2新增建议，明确区别于上传代码已有入口。所有写入仍从Governance经过现有认证、租户资格、模块与角色检查；内部仅gRPC，不新建对外HTTP服务。

## 1. 应用配置增量

保留已有`ANI_QUOTA_ENABLED`及内部释放监听/TLS配置。以下新配置建议放既有配置加载模块中，环境名须最终登记；不能靠配置加载一个未知owner/任意URL作为运行插件。

| 新键 | 类型/默认 | 说明 |
|---|---|---|
| ANI_GPU_INFERENCE_ENABLED | bool / false | 注册正式Inference GPU创建/删除能力，缺必需连接信息时启用失败；禁用不抹掉已有账本 |
| ANI_ACCELERATOR_GRPC_ADDR | string / 空 | GPU服务受管地址，启用时必填，不接受客户端提供 |
| ANI_INFERENCE_GRPC_ADDR | string / 空 | 真实Inference地址；需核对现有配置是否已有可复用项 |
| ANI_RESOURCE_CLIENT_CA_FILE | path / 空 | 出站受管CA文件引用，可复用已有配置；不能明文降级 |
| ANI_RESOURCE_CLIENT_CERT_FILE | path / 空 | Gov客户端证书，服务端精确验证Gov身份 |
| ANI_RESOURCE_CLIENT_KEY_FILE | path / 空 | 私钥只从文件/secret载入，不进业务数据库或日志 |
| ANI_ACCELERATOR_SERVER_NAME | string / 已登记服务身份 | TLS校验目标，不能skipVerify |
| ANI_INFERENCE_SERVER_NAME | string / 已登记服务身份 | TLS校验真实owner目标 |
| ANI_GPU_USAGE_SYNC_INTERVAL | duration / 5s建议 | 独立旁路扫描周期，不是资源清理/退款TTL |
| ANI_GPU_USAGE_SYNC_BATCH | int / 50建议 | 单页扫描量；定期扫描既有未收敛/旧原操作，不能只扫新create |
| ANI_GPU_USAGE_SYNC_RPC_TIMEOUT | duration / 3s建议 | 超时重试同步，不取消工作负载 |

factor不放Governance环境变量。它属于GPU服务各静态组的已验证基线，Resolve返回编码参数；Gov只按MiB计量。创建已受理后计划不受新配置重新解释。

构造函数只装配依赖，worker由现有应用Start/Stop管理；密钥权限、日志脱敏复用已有实现。投影worker不调用业务创建方法，不修改业务dispatch_state/attempt_count。

## 2. 新BFF建议路径与字段

路径仅为本次建议，真实Inference业务路径未随上传源码提供，不发明一套替代业务API。JSON数量遵循对应Proto，64位整数使用十进制字符串，小的replicas/devices使用JSON数字。列表统一映射已有分页，不借本任务改全平台包装。

| 方法/路径 | 主要输入字段 | 调用合同/主要输出 |
|---|---|---|
| GET /admin/v1/accelerator/clusters | pageSize,pageToken | Admin.ListClusters；items[{clusterId,displayName,connectionRef,version}]，nextPageToken；connectionRef为引用非密钥 |
| POST /admin/v1/accelerator/clusters | data{displayName,connectionRef}，Idempotency-Key | RegisterCluster；管理员初始化 |
| GET /admin/v1/accelerator/pools | clusterId,pageSize,pageToken | ListPools；items[{poolId,clusterId,displayName}] |
| POST /admin/v1/accelerator/pools | data{clusterId,displayName} | CreatePool；初始化 |
| GET /admin/v1/accelerator/supply-groups | poolId,pageSize,pageToken | ListSupplyGroups；当前静态模式、已生效配置摘要和入口状态 |
| POST /admin/v1/accelerator/supply-groups:adopt | data{poolId,displayName,mode,nodes,modelKey,baseline,queueName} | AdoptSupplyGroup；仅初装，不下发切卡；baseline由受控证据核对 |
| POST /admin/v1/accelerator/supply-groups/{groupId}:set-admission | data{expectedVersion,desired,reason} | SetAdmission；仅阻止新Resolve |
| GET /admin/v1/accelerator/profiles | clusterId,pageSize,pageToken | AdminListProfiles；平台目录，无假租户 |
| POST /admin/v1/accelerator/profiles | data{displayName,spec,expectedGroupVersion,verificationRef} | PublishProfile；首期初始化固定规格 |
| GET /admin/v1/accelerator/devices | clusterId,groupId?,pageSize,pageToken | ListDevices；物理bytes、位置、健康、来源时间 |
| GET /admin/v1/accelerator/bindings | clusterId,physicalDeviceId?,pageSize,pageToken | AdminListBindings；含未关联占用、实际父卡和可信归属 |
| GET /admin/v1/accelerator/capacity | profileId,profileVersion,includeDevices | AdminGetCapacity；明确AdminRead |
| GET /api/v1/accelerator/profiles | clusterId,mode?,pageSize,pageToken | ListProfiles；当前租户可见规格 |
| GET /api/v1/accelerator/capacity | profileId,profileVersion | GetCapacity；只汇总，不返回devices |
| POST /api/v1/accelerator/admission-preview | data{gpu:GpuRequest} | BFF组合Resolve、Gov账户、CheckGpuFit；不写账本或占位 |
| GET /api/v1/accelerator/usages | ownerService?,state?,pageSize,pageToken | ListGpuUsages；经下述公开DTO脱敏，非直接透传完整内部投影 |
| GET /api/v1/me/quota-accounts | 无tenant字段 | 当前Principal对应Gov账户，复用现有QuotaAccountView，限定自身 |

新增模块及角色授权必须在正式接口登记中确定，不默认全部TENANT角色可用。Admin初始化可先CLI，不要求首期完成所有POST页面；但其授权与业务校验相同。

## 3. 租户公开使用关联DTO

内部完整投影用于可靠同步及查询关联；租户页面不需要全部计划/来源证据，建议只输出：

| 字段 | 类型 | 语义 |
|---|---|---|
| resourceId | string UUID | 本租户业务资源 |
| ownerService | string | ani-inference等已开放owner |
| profileId/profileVersion | string/string整数 | 采用的固定规格 |
| gpuMode | string | WHOLE_EXCLUSIVE/SHARED_FIXED |
| replicas | number | 冻结请求副本数 |
| devicesPerReplica | number | 首期1 |
| logicalGpuCount / exclusiveGpuCount | string整数 | 对应产品数量，另一项0 |
| requestedSharedMemoryMib | string整数 | 仅共享申请总量，非实时指标 |
| associationState | string | DECLARED/ENDED；不是Ready/Failed |
| associationSynced | bool | 从该接口成功读取为true；Inference资源列表匹配不到时可显示false，不推断资源不存在 |
| actualBindingSummary | object可空 | 仅可信本租户关联后的数量与完整度，实际设备身份由权限决定 |

不返回source_fact_ref、完整plan/runtime/证书配置、其他租户标签、原始UUID注解或未核验身份。业务创建时间/模型状态和Ready仍从Inference读。管理员可以通过独立接口看到更完整事实。

## 4. 预检响应字段

| 字段 | 类型 | 含义 |
|---|---|---|
| requestedQuotaItems | array{quotaCode:string,units:string} | 服务端对本次请求计算的MiB或整卡数量，仅提示 |
| quotaChecks | array{quotaCode:string,result:string,limit:string,occupied:string,requested:string} | 使用已有当前租户账户；正式提交事务内再验 |
| gpuFit | GpuFit脱敏 | 当前GPU条件，不包括CPU、网络和存储自动通过 |
| additionalReplicasByQuota | string整数 | 仅额度限制下可新增副本数；不含已有预留消费 |
| capacityReferenceReplicas | string整数 | GPU读模型参考数量，不是提交数量上限 |
| capacityReferenceKnown | bool | false不得将0显示为全池耗尽 |
| submissionPolicy | string | 固定WAIT_IF_CAPACITY_UNAVAILABLE；不构成最终授权 |
| otherChecks | array{code:string,status:string} | 例如CPU/STORAGE/NETWORK=NOT_CHECKED |

不需要把factor下发给前端供用户修改；后台细节面向管理员诊断即可。

## 5. 正式创建与删除的接线检查

Gov保留原公开Inference业务字段，在原请求上加入gpu。容器名、副本数不能存在两份互相矛盾的来源；如果已有业务字段则服务端只派生一份GpuRequest，或明确拒绝不一致。

创建的GPU附件见`GpuOwnerCreateAttachment`。同步只是旁路，不改变业务接受ACK；Gov仅记录ACKED，查询业务状态继续转真实owner。

正式删除公开结果采用`GpuDeleteAcceptance`建议：deleteOperationId/resourceId/result/dispatchOperationId。result为CANCELED_BEFORE_DISPATCH时没有owner执行，不填假ACK；QUEUED_FOR_OWNER只表示接受，不能即刻显示删除完成。不同DELETE key仍指向同一实例的最终删除事实，owner不重复退额。

管理员代租户清理需显式权限、明确目标tenant、审计原创建关联，仍走同一个删除受理函数。原用户过期不产生强制减账后门。
