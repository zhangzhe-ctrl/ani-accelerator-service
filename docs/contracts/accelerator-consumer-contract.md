# GPU absolute-memory consumer contract

ACC supplies immutable GPU execution data; Governance owns identity, original quota charges and durable dispatch; Resource owns its workload and complete-release facts. This contract replaces the previous full Plan and owner attachments without a runtime conversion path.

## Service authorization and tenant isolation

Governance is the authorization authority for user identity, account state, roles, platform administration, subscription modules and quota admission. It derives the actor and resource-tenant UUID from its authenticated principal and persisted tenant mapping, and reconstructs outbound metadata rather than forwarding public caller identity fields. New users and tenants require no ACC configuration change or restart. ACC has no per-user or per-tenant deployment allowlist.

ACC requires TLS 1.3, a verified managed CA chain and exactly one DNS SAN on each caller certificate, with no URI, IP, email or additional SAN entry. The fixed registered identities are `security.governance_dns_name=ani-governance`, `inference_dns_name=ani-inference-service`, `resource_dns_name=ani-resource-service` and `modeldev_dns_name=ani-modeldev-service`. CN, SPIFFE URI aliases, wildcard names and alternate identities are not accepted. The Inference transport identity maps to persisted owner `ani-inference`; ModelDev maps to owner `ani-modeldev-service`.

| Caller | Exact RPC allowlist |
|---|---|
| Governance | The generated full method names of AcceleratorAdminService, AcceleratorCatalogService, and the usage reads `GetGpuUsage`, `ListGpuUsages`, `ListBindings`; background `SyncGpuUsage`; gRPC Health `Check`, `List`, `Watch` |
| Resource, Inference and ModelDev | Only `/accelerator.v1.AcceleratorUsageService/ObserveRelease`, for the authenticated service's own resource reference |
| Other identity or method | Denied, including a known short method name under another service/package, reflection and other streaming methods |

Adding a generated RPC does not automatically authorize it: ACC explicitly registers each complete method path. Health access is also a service permission, not a user grant. Resource, Inference and ModelDev cannot use ACC health methods, SyncGpuUsage or directory/management RPCs.

Delegated Gov calls retain `x-ani-action`, `x-ani-actor-type`, `x-ani-actor-id`, and tenant-scoped calls retain `x-ani-tenant-id`. Metadata must be unique and match the typed request context; admin requests must not carry a tenant scope. ACC retains the actor for audit, cursor binding and idempotency rather than looking it up in a deployment list. Usage and Binding reads retain tenant predicates and full tenant-preserving resource references; conflicting tenant context and cross-tenant cursors or associations are rejected. Shared Profile/Pool/SupplyGroup catalog entries remain platform data, scoped by their managed cluster and parent relations.

`SyncGpuUsage` is a durable Gov background fact and carries no delegated user or tenant metadata; an optional action must be `SyncGpuUsage`. `ObserveRelease` carries the tenant, action and the authenticated owner's durable deletion scope. Lifecycle synchronization, physical release and original-charge refund do not depend on the initiating user still holding a role or an active subscription.

ACC's infrastructure scope comes directly from the existing `provider.json` `connections[].ref` values and the persisted cluster `connection_ref`. `RegisterCluster` can reference only a configured connection. Directory, resolution, capacity and management operations verify that stored cluster relations remain in this provider domain. Unknown or removed connections, unknown clusters and conflicting entity parents are rejected. There is no second service/cluster list and no user/tenant-to-cluster mapping. Connection credentials and endpoints cannot be supplied through public RPCs; the [provider configuration contract](../runbooks/provider-sources.md#受管连接配置) owns them.

Migration removes `security.grants` and the previous `*_uri` fields; their protobuf field names and numbers remain reserved. Pre-cutover cursor tokens fail their changed scope hash and callers must restart pagination; persisted actor-based mutation idempotency is unchanged. Old fields are rejected rather than ignored as a permissive default. Replace service certificates and configuration together, preserving a matching previous binary/configuration/certificate set for recovery. A user permission or subscription denial is a Gov decision; an ACC service identity or RPC-policy denial is a dependency authorization failure, not a request for the user to obtain another role.

## Resolve and execution

`ResolveGpuRequest` returns `ResolvedGpuRequest` with `execution`, `quota_items` (Governance only), and `selection` (display only). `GpuExecution` contains exactly scheduler, queue, RuntimeClass, node selector, Pod annotations, resources and execution digest. Number, memory and cores appear once, in resources. The only supported resource keys are `volcano.sh/vgpu-number`, `volcano.sh/vgpu-memory`, `volcano.sh/vgpu-cores`. Profile memory and shared quota remain MiB; the memory resource is a provider block count with actual device-plugin F=1 or F=10. Percentage and unknown resource keys are rejected.

Factor belongs to the immutable managed installation baseline, not a tenant, Profile or instance setting. Nodes in one group must use the same effective factor. ACC encodes exact `MiB / F`; a non-divisible requested size is rejected, never silently rounded. PreviewProfile quantizes its explicit 2/4/8-parts suggestion to full blocks and reports unused MiB. Provider registration and scheduler/allocation values are decoded from blocks once; actual runtime MiB and physical bytes are not multiplied again. Per-card quantization discards each card's tail independently.

New F=10 execution carries `accelerator.ani.io/memory-block-mib=10` in its frozen Pod annotations, covered by the existing execution digest. No annotation means the existing F=1 execution contract; F=1 rendering and historical digests stay unchanged. When present, this annotation accepts only the literal `10`; an explicit `1`, alternate formatting, or another value is rejected. Memory decoding checks overflow. Owners persist and render the complete execution unchanged, including this annotation. Display reads `GpuMemoryMiBPerDevice` from the frozen execution, never the current installation or raw block count. Stop/Start and original quota refunds do not re-resolve units. Changing effective F requires a new baseline and a controlled infrastructure migration that accounts for old workloads and in-flight creation; it is not an online Profile edit.

RuntimeClass comes from ACC's managed baseline, with no owner fallback. Inspect reads the exact registered `node.k8s.io/v1` RuntimeClass through the existing managed cluster connection and requires its name, UID, resourceVersion and handler. The three supply-group/model-key/baseline identity selectors remain mandatory and fixed. The only supported additional scheduling selector is `kubernetes.io/hostname`, a nonempty Kubernetes label value of at most63 bytes; every original group Node UID must still match and carry that exact label. Missing RuntimeClass facts, unknown/conflicting selectors, nonempty overhead and tolerations reject new resolution. The observed selector is merged before computing `execution_digest`; accepted executions are never recompiled when the RuntimeClass changes. Shared memory is positive MiB and cores 1..99. Whole mode requests the actual complete per-device usable memory and 100 cores, with K=1. Profile parameters are immutable; changing them requires a new Profile ID.

`pkg/gpuprotocol` exports `GpuExecutionDigest`, `ValidateGpuExecution`, and `GpuMemoryMiBPerDevice`. The digest is SHA256 of `acc-execution-v1\n` plus canonical UTF-8 JSON of the explicit six execution fields, excluding the digest. Keys sort lexically; resource values are decimal strings; HTML escaping and trailing newlines are absent. Display and mutable catalog state do not enter this digest.

The common persisted-command ACK lives in `accelerator.command.v1`. Deleted protobuf field numbers and names are reserved. Retired Plan, Encoding, Totals and GPU owner attachment messages are absent from the generated API.

## Catalog and physical inventory

Management RPCs are CreateProfile, PreviewProfile, SetProfileState, DeleteProfile, AdminListProfiles. Profiles have ACTIVE/DISABLED/DELETED state and a revision. Mutations use idempotency and CAS; deletion is soft. The authorized catalog retains inactive entries so consumers can show an unavailable reason. New Resolve requires ACTIVE; previously accepted execution data is independent of subsequent catalog state.

Multiple profiles may share a group. Their capacities are alternative views of one physical ledger and cannot be added. Per-card usable memory is the minimum of actual registered memory and quantized NVML memory. Missing or conflicting automatic sources produce Unknown and retain occupancy. No test report, verification reference, artificial qualification state or expiry gates catalog creation, admission, resolution or collection.

## Ownership, Usage and release

Each owner signs actual cluster/namespace/Pod name/Pod UID/container, tenant/owner/resource/create-operation and execution digest using `pkg/gpuprotocol.OwnerAssertionSigningBytes(pod, ref, executionDigest)`. This public helper and the provider verifier consume the existing `acc-owner-pod-v2\n` domain and canonical payload without a format change. ACC verifies the key registered for that exact owner; a label or digest alone does not authenticate ownership. Inference, Resource and ModelDev keys are independent; registering ModelDev with another configured owner's public key is rejected. ModelDev supplies `accelerator.modeldev_owner_public_key_file` as an absolute path to the Base64 raw 32-byte Ed25519 public key. The private key stays with ModelDev. An absent ModelDev key leaves physical allocations counted and unassociated; another owner's key cannot authorize them. For current single-worker Trainer execution, sign the actual Trainer Pod UID and container `node`, after creation, rather than the TrainJob object or an anticipated Pod UID.

Governance asynchronously sends the thin Usage projection: reference, profile/group/configuration references, cluster/container, execution digest, source creation time, revision/state/end reason/fact reference and payload digest. ACC checks immutable reference identity without recalculating execution or quota from today's directory. ENDED does not erase a live binding. Workload creation does not await Usage delivery.

`ObserveRelease` requires the authenticated owner's reference, delete/close operation, cluster, persisted `sealed_at` and known historical Pod references (which may be empty). The close UUID must be distinct from the original create UUID; equality returns `INVALID_RELEASE_SCOPE`. ModelDev persists one independent close UUID and retries the same accepted scope, including its original seal and actual historical Pod UID/container references. This is an owner service call with unique `x-ani-action=ObserveRelease` and `x-ani-tenant-id`; it does not impersonate a live user. ACC supplements the scope from durable owner claims and rejects cross-cluster conflicts. Every managed GPU node must have complete, fresh Kubernetes, PodResources and CRI watermarks at or after the seal. Known allocations require positive runtime-exit, allocation-absence and online-node evidence; durable release facts do not expire while current source health is checked. Missing sources or unassociated allocations remain Unknown. A sealed scope with no observed allocation can complete only after this full source check.

Complete resource release is reported to Governance through its quota API `ReportResourceReleased`: release event, original create operation, resource and reason only. Resource neither receives nor persists charges. It seals creation, resolves unknown writes and confirms physical release before creating the release outbox; only a matching terminal ACK completes that outbox. Stop/restart/ordinary exit do not cause full quota return. Governance refunds the authenticated owner's original remaining charges exactly once.

## Deployment and verification boundary

Explicit migration 0004 removes the single-profile constraint, updates new-write identity checks and protects immutable Profile parameters. Startup never migrates. Cutover requires old workloads, in-flight writes and release delivery to be closed; old audit facts are preserved and are not interpreted as new execution payloads. F=10 adds no database migration or protobuf field; deployment requires coordinated consumer contract versions and actual plugin configuration matching its baseline. An old consumer that only accepts F=1 must not receive F=10 work.

Explicit migration 0005 extends only the finite usages/claims/release-proofs owner set to ModelDev, preserving tenant/identity/execution checks. The new runtime requires schema 5 and never executes this migration at startup. Back up the populated database and apply the reviewed migration with its migration owner before switching the coordinated binary, DNS identity configuration and ModelDev public-key mount. This migration does not change scheduler, profiles, quota or active workload resources.

Existing software acceptance records cover generation/sqlc consistency, PostgreSQL, mTLS/process recovery, race, tenant mutations, transactional restore, vulnerability and secret scans, and the ordinary production executable with explicit external infrastructure substitutes. Each record applies to its recorded source snapshot. The authorization change requires directed Fedora checks for the real Gov→ACC catalog path, new principals without ACC onboarding, service/RPC rejection, tenant isolation and existing background/release behavior. Local work is source editing only; generation, builds and tests run on Fedora. This change does not authorize deployment. Software checks do not constitute real GPU acceptance; shared/whole CUDA, physical release and official scheduler acceptance remain separate.
