# GPU 绑定按当前状态对账

本次简化以 `5489bcbf50b28c73204151808e97cea6c51759bc` 为基线。普通释放不再要求全部历史 attempt 有退出时间，也不自动查询 containerd journal。

## 当前规则

ACC 接受认证节点上完整、新鲜的 CRI 和 PodResources 当前事实，并结合当前 Kubernetes Pod 生命周期判断旧绑定是否继续计占。

| 当前事实 | 处理 |
|---|---|
| Pod 未删除、未终态，正在 Pending、启动或重启 | 保留有效调度预留 |
| 当前仍有 CREATED、RUNNING 或 UNKNOWN 容器 | 保留占用 |
| 当前仍有无法归属的相关容器或设备分配 | 当前范围保持未知/占用 |
| 当前没有旧工作负载的运行占用、设备分配及有效预留 | 退休已覆盖的旧 claim |
| 当前仅有 EXITED 容器，历史退出时间缺失 | 接受当前 EXITED 状态，不补历史日志 |
| 节点失联、会话失效或当前来源不完整 | 不以空结果退休 |
| 旧历史 attempt 缺字段或历史事件缺口，但完整新快照已覆盖 | 不再阻塞当前对账 |

当前运行视图包含完整快照，以及采集起点之后尚未被后续完整快照覆盖的增量；因此“空快照之后收到 Running”仍能阻止退休。历史容器 GC、事件遗漏或超过十六次重启，不会成为正常容量恢复的永久条件。

绑定已退休、Pod 也已从 API 消失后，如果又观察到该已知绑定的当前运行或设备分配，会重新计占。终态 Pod 首次被采到时，仍在的设备分配也不会因缺少历史 binding 而漏记。

同名新 UID 的 Pod 不继承旧 UID 的占用身份。PodResources 不携带 UID，因此现有分配仅在当前新 Pod 的运行容器能够明确解释时，才可作为新 UID 的分配处理。

## 持久化和并发

沿用 `ReleaseProof` JSON 载体和 `RELEASE_CONFIRMED` 绑定状态。新原因 `retirement=CURRENT_STATE_RECONCILED` 表示当前占用已对账，不声称逐一见证历史退出。旧 `RuntimeExited`、`AdmissionRejected` 模式保留读取与归并语义；准入失败旧证明仍仅退休 scheduler claim。

新记录必须关联同批次的节点修订号，由既有节点事务锁检查。当前视图成员或状态变化会推进修订，单纯更新时间不会。退休时间采用采集起点和有效源时间的共同下界，不能消除更晚到达且时间更新的占用。

节点状态保存当前快照尚未覆盖的运行增量；新完整快照覆盖后移出该当前视图，原始历史不删除。旧状态首次建立这一视图时补读一次历史，以保留落在采样窗口内的增量；之后继续按报告涉及的容器 ID 读取，不在每次上报时扫描历史。

无需表结构迁移、公开 API 或 node-agent 协议升级。旧 ACC 二进制不认识新增退休原因，回滚旧版本会重新采用旧判定并可能恢复历史占用，因此不能把旧版本回滚当成本次行为的兼容运行方式。

## 责任与范围

ACC 仍提供供给观测和容量估算；最终调度与设备接纳由现有执行链处理。Governance 继续负责创建占额、最终删除退额；Usage ENDED 不清除活绑定。公开 ObserveRelease RPC 继续保持下线。

本次删除普通释放中的 journal 补证调用及其解释辅助逻辑，删除只允许 UnexpectedAdmissionError 的特殊释放分支，并解除当前运行视图与全部历史 attempt 的依赖。历史诊断记录仍保留；没有历史数据清理、全量容量聚合策略重构或环境部署。

## 验证范围

必要回归覆盖当前空快照与 37 条旧 UNKNOWN、Pending/重启预留、当前运行和来源故障、普通 Failed/删除生命周期、同名新 UID、采集窗口内及之后的运行增量、节点修订冲突、旧证明兼容及 PostgreSQL 归并。

测试代码不是执行结果。实际构建、测试和部署状态以本次 PR 的验证记录为准；历史 PASS 记录不适用于本次修改。
